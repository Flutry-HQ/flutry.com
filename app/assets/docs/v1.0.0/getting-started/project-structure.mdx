The starter project keeps application code under `src` and separates the server entry point, routes, and models.

```text
src/
  main.ts
  routes/
    index.route.ts
  models/
    test.model.ts
  utils/
```

## `src/main.ts`

This is the bootstrap boundary. It loads environment variables, creates `HttpServer`, conditionally creates `Connect`, and starts listening.

## `src/routes`

Route discovery scans this directory recursively for files ending in `.route.ts` in development, and the corresponding built route files in production. Every discovered module must have a default class export extending `Router`.

Directory and file names become URL segments:

| File                            | Route prefix     |
| ------------------------------- | ---------------- |
| `routes/index.route.ts`         | `/`              |
| `routes/users/user.route.ts`    | `/users`         |
| `routes/users/profile.route.ts` | `/users/profile` |
| `routes/users/$id.route.ts`     | `/users/:id`     |

The configured `prefix` is applied to each route after this conversion.

## `src/models`

The database package recursively scans `src/models` outside production and `dist/models` in production. Files must match `.model.ts`, `.model.js`, `.model.mjs`, or `.model.cjs`, export a default class, and provide a static `initialize(sequelize)` method.

```ts
export default class Test extends Model {
  static initialize(sequelize: Sequelize) {
    Test.init(
      {
        id: { type: DataTypes.STRING, primaryKey: true },
        message: { type: DataTypes.STRING, allowNull: false },
      },
      { sequelize, tableName: 'test', timestamps: false },
    );
  }
}
```

After all models load, optional `associate` methods are called and Sequelize synchronization runs. Development uses `sync({ alter: true })`; production uses normal `sync()`.

> **Naming matters**
>
> A correctly exported model with a different filename is not discovered. Keep the `.model` suffix and the default export contract.
